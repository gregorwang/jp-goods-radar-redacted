# 关键词日报去重 / 聚合 —— 待规划（2026-09-28）

## 为什么要做

- 「爱蜜莉雅」关键词日报每天 100～130 条，2026-09-23 那天一共找到 567 条。
- 以前邮件最多只放 100 条，超出部分标记为"已发"后就再也不会出现，等于被静默丢掉。
  2026-09-28 已经改成"有多少放多少"（`packages/db/src/queries/digests.ts`、
  `packages/email/src/templates.ts`），这只是临时做法：不再丢，但也更长了。
- 一天几百条没人看得完。按 AGENTS.md §4，误报多了的最终结果还是漏报。

## 数据告诉我们的（2026-09-27 那封爱蜜莉雅日报，前 100 条）

| 指标 | 数值 |
|---|---|
| 条目数 | 100 |
| 不同标题 | 94 |
| 去掉空格、括号、「新品 / 未開封 / 中古」等词之后仍然不同的标题 | 93 |
| 来源分布 | Mercari 48 · 雅虎闲置 27 · 雅虎拍卖 21 · 乐天 3 · 骏河屋 1 |

结论：**字面重复只占约 6%**，单靠"标题一样就合并"效果有限。量大的主因是关键词本身覆盖太广
（エミリア 出现在几百种周边里），而不是重复。

能看到的几类"其实是同一件事"：

1. **同一卖家跨平台挂同一件**：`SPM フィギュア エミリア 大精霊パック` 在 Mercari、雅虎闲置、
   雅虎拍卖各一条，价格都是 2,500。→ 应合并成一张卡，列出三个购买入口。
2. **同一卖家的批量上架**：`【ACF0453】【ACF8586】【ACF8592】…クリアファイル` 这种带管理编号的一串，
   同一个店铺、同一品类、价格几乎一样。→ 可以折叠成"某店上架了 N 件クリアファイル"。
3. **同款不同卖家**：几个 `コスプレ衣装`、几个 `ESPRESTO エミリア フィギュア`（1,050 / 1,350）。
   → 聚合成一张"同款卡片"，展示价格区间和最低价入口，这也是比价最有用的形态。

## 可能的方向（待讨论，不是结论）

- **同款聚合卡片**：一张卡片 = 一件商品，下面挂多个平台 / 多个卖家的入口和价格区间。
  难点在"判断是不是同一件"，字面规则只能兜住 1、2 类；第 3 类大概率要 AI 判定，
  需要先算清楚每天几百条的 AI 成本。
- **按品类分组 + 折叠**：手办 / 亚克力 / 卡片 / 服饰……每组默认展开前几条。
  确定性强，成本低，但不减少总条数，只是更好扫。
- **档案层面收窄**：给宽泛的关键词档案加品类或价格条件。这是用户自己的选择，
  系统不能替用户定（AGENTS.md §4：送达门槛每个档案一个设置）。
- **邮件只放摘要，完整列表放网页**：Gmail 超过约 102KB 会折叠正文，几百条带图的
  邮件大概率会触发，需要点"查看完整邮件"才能看全。

## 已做：屏蔽卡牌游戏卡（2026-09-28，档案设置，未改代码）

用户不要集换式卡牌（贵、不收）。用的是档案已有的「排除词」，在爱蜜莉雅档案追加了两条：

- `ヴァイスシュヴァルツ|Weiß Schwarz|Weiss Schwarz|Reバース|ユニオンアリーナ|UNION ARENA|ChaosTCG|カオスTCG`
- `PSA10|PSA 10|PSA9|PSA鑑定|CGC 10|BGS|TCG|SEC+|RZ/S|RZ/0`

用 09-21～09-28 的 1074 件回放：挡掉 84 件（约 8%，每天约 12 件），逐条核对全是卡牌，无误伤。
故意没加的词：`トレカ`（有手办卖家在描述里写"トレカ"，会误伤）、`サイン`（会误伤签名色纸）、
`カード`（会连明信片、亚克力卡、特典卡一起去掉，用户选了保留）。
排除词在抓取阶段生效，被挡的商品不进 AI 判定，也省调用费；收窄不会触发基线重置。
要撤销：在管理后台删掉这两条即可（放宽会触发一次静默重建基线，不会补发旧货）。

结论：这只削掉一小部分，每天 100+ 条的主因仍是下面说的"关键词覆盖太广"，去重/聚合仍要单独做。
