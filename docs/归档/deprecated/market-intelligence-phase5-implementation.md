# 行情情报 Phase 5：到手成本与商品生命周期实施契约

更新日期：2026-07-19
实施范围：`cost profile`、到手成本区间、单 listing 价格/状态时间线、疑似重挂候选、目标到手价事件。

## 1. 这一阶段回答什么

Phase 5 只回答两个新问题：

1. 当前某条确认同款报价，在一份明确且版本化的成本配置下，预计到手成本是多少范围。
2. 系统实际观察到每条 listing 经历了哪些价格/状态变化，以及多个 listing 是否存在保守的“疑似重挂”证据。

它不生成稀缺度、流动性、deal score 或真实成交结论；这些仍属于后续 Phase 6。来源 `sold_out`、页面消失、`left_visible_window` 都不等于 verified sale。

## 2. 当前系统地图与复用决策

| 能力 | 当前事实来源 | Phase 5 决策 |
| --- | --- | --- |
| 稳定商品身份 | Supabase `canonical_products`、`product_variants`、版本化 memberships | 复用，不改身份规则 |
| 可比公开标价 | Supabase `source_listings` + comparison profile | 复用，不把到手成本混入原始标价 |
| 搜索观察 | Supabase `listing_observations` | 复用为生命周期原始证据 |
| 单品监控快照 | D1 `listing_snapshots` 经 outbox 同步到 Supabase `operational_listing_snapshots` | 复用为生命周期原始证据 |
| 用户监控规则 | D1 `monitor_rules` + `monitor_events` | 追加到手价目标扩展，不重建旧表 |
| 用户成本偏好 | 目前不存在 | D1 新增不可变版本 `cost_profiles` |
| 到手成本 | 目前不存在 | 读取时用确定性纯函数派生，不写回 listing |
| 生命周期 | 目前无独立结论表 | 从两类 observation 有界推导，不复制证据 |
| 重挂关系 | 目前不存在 | 读取时输出保守候选，不永久合并 listing |

### 为什么成本配置放 D1

本项目目前是单管理员操作系统，D1 已负责登录后的监控偏好、规则和运行状态。成本配置属于用户操作偏好，不是市场原始证据，因此放在 D1。每次修改新增版本并关闭旧版本；已保存的监控规则固定引用当时的成本配置版本，后续修改不会改写历史事件含义。

### 为什么生命周期暂不新增 Supabase 表

现有 `listing_observations` 和 `operational_listing_snapshots` 已能表达搜索观察与监控快照。Phase 5 的时长、价格变化、状态变化都是可重算的确定性派生。当前新增一张生命周期“事实表”会重复证据并引入一致性问题，收益不足。

## 4. 领域词典

| 名称 | 精确定义 | 禁止替代文案 |
| --- | --- | --- |
| 商品标价 | 来源公开的 JPY listing price | 到手价、成交价 |
| 到手成本区间 | 商品标价加成本档案中的国内运费、代购费、国际运费、税费和缓冲后得到的 JPY 范围 | 精确到手价（存在未知重量时） |
| 成本档案版本 | 一组人工配置的费用规则快照 | 实时物流报价 |
| 系统观察活跃时长 | first seen 到首次 unavailable observation 的天数 | 售出用时 |
| 右删失 | 截止当前仍 active，只知道活跃时长至少到最后一次观察 | 0 天、已售 |
| 来源已售状态 | 来源页面公开状态为 `sold_out` | 已验证成交 |
| 疑似重挂 | 同来源、同卖家、同图、相近标题、不同 source item id 的候选关系 | 同一件商品（未经确认） |
| 独立供给估计范围 | 原始 appearance 数与“所有疑似重挂均为同一供给”两种边界形成的范围 | 唯一精确出现次数 |

## 5. 到手成本计算契约

### 5.1 成本档案字段

- 汇率：每 100 JPY 对应多少 CNY，仅用于辅助展示；监控与主计算保持 JPY。
- 汇率缓冲百分比：只作用于 CNY 辅助换算上界。
- 代购固定费与按商品标价计算的比例费。
- 日本国内运费默认最小/最大值。
- 国际运输线路名称、首重克数与首重费用范围、续重克数与每档费用范围。
- 未知重量的最小/最大克数。
- 合箱分摊比例；100% 表示本件承担全部国际运费估计。
- 税费开关与税率。
- 总成本缓冲百分比。

所有百分比在存储层使用 basis points，汇率使用定点整数，不使用浮点数持久化。

### 5.2 计算顺序

1. 读取有效 JPY 商品标价；非 JPY 或缺少标价时返回 `unavailable`。
2. 优先读取 listing 中有证据的日本国内运费与重量；缺失时使用成本档案默认范围。
3. 代购费 = 固定费 + 商品标价比例费。
4. 国际运费按首重/续重与重量范围分别计算上下界，再应用合箱分摊比例。
5. 税费按“商品标价 + 国内运费 + 代购费 + 国际运费”计算。
6. 总成本缓冲最后作用于上述小计。
7. 下界向下取整、上界向上取整；未知重量必须保留范围。

输出必须包含成本档案 ID/版本、各分项区间、重量来源、缺失事实、JPY 总区间和 CNY 辅助区间。它是配置估算，不是物流商报价。

### 5.3 目标到手价事件

`product.offer_below_target_landed_cost` 只对稳定 `exact_product` variant 开放。规则固定引用一份成本档案版本，并采用保守策略：

```text
estimate.maxJpy <= targetLandedCostJpy
```

只有整个估算区间都不高于目标值才触发。区间跨过阈值时不通知，避免用乐观下界制造“低于目标”的假消息。事件 payload 保存成本档案版本、上下界、阈值和策略。

## 6. 生命周期与疑似重挂契约

### 6.1 Observation 合并

- 每条确认同款 listing 分别读取搜索 observation 与操作快照。
- 每条 listing 最多读取最近 100 条，避免无界响应。
- 以 `observedAt + price + availability + condition` 去重并按时间升序排列。
- 只在同一 listing 内把连续价格/状态点形成时间线；不同 listing 永不连成同一条曲线。

### 6.2 时长

- `observedActiveDurationDays` 仅在系统先观察到 active，之后又观察到首次 unavailable 时计算。
- 截止当前仍 active 的 listing 标记为 `rightCensored=true`，展示“系统已观察至少 X 天”。
- 一开始就处于 `sold_out`/`unavailable` 的历史记录不反推售出用时。
- `verifiedTimeToSaleDays` 在没有 verified sale 证据时始终不输出。

### 6.3 疑似重挂

候选必须同时满足：

1. 同一来源、不同 source item ID；
2. 规范化卖家相同且两边都不为空；
3. 规范化图片 URL 相同且两边都不为空；
4. 标题相似度达到版本化阈值。

输出为 `candidate`，包含可复查证据和相似度；不写回 membership，不删除 listing，不折叠价格样本。appearance 只给 `candidateAdjustedRange`：上界为原始 listing 数，下界假设每个候选 cluster 只代表一件独立供给。

## 7. 数据状态与 UI 文案矩阵

| 状态 | UI 输出 | 主动作 |
| --- | --- | --- |
| 没有成本档案 | 不计算到手价，解释缺失原因 | 配置成本档案 |
| 有档案、未知重量 | 显示到手价范围和“重量使用档案范围” | 可设置保守目标到手价 |
| 有档案、商品价缺失/非 JPY | 显示不可估算原因 | 打开来源核实 |
| 当前 active | 单 listing 时间线标记右删失 | 监控降价/目标到手价 |
| 来源 sold_out | 只显示来源状态与观察点 | 商品级重新出现监控 |
| 疑似重挂 | 显示候选组和供给数量范围 | 查看候选证据；不自动合并 |
| 无疑似重挂 | 明确“当前规则未发现候选”，不宣称绝无重复 | 继续积累观察 |

## 8. 迁移、开关与回滚

- D1 追加迁移 `0033_landed_cost_and_lifecycle.sql`。
- 新增 `landed_cost_v1` feature flag；关闭后成本档案只读、到手价不参与新事件判断。
- 不修改 Supabase 原始证据表，不需要历史 backfill。
- 不重建带 `target_landed_cost IS NULL` 约束的旧 `monitor_rules`；使用一对一扩展表保存目标值和成本档案引用。
- 回滚应用时关闭 `landed_cost_v1` 即可。新表和历史版本保留，不删除证据或规则历史。

## 9. 验收重点

1. 未知重量返回非零区间，不能坍缩成伪精确点值。
2. 到手价目标只在上界低于等于阈值时触发。
3. 已售状态不出现单品降价监控，也不生成 verified sale。
4. active listing 以右删失展示，不当成 0 天。
5. 不同 listing 的折线不相连。
6. 同卖家、同图、相似标题的新 ID 只标为疑似重挂，并给 appearance 上下界。
7. 修改成本档案产生新版本；旧监控和历史事件仍引用旧版本。
8. 关闭 feature flag 后不产生新的到手价事件，原始采集与价格情报不受影响。
