"空"有三种：**真的没有**、**没查成**（网络/被拦）、**查了但解析失败**。系统必须分得开，否则"页面变了"会伪装成"今天没货"。

## 发现的问题（按影响排序）

1. **关键词档案 AI 的 `relevance` 字段坏了会被兜底成 `uncertain`**：`packages/validation/src/index.ts:756` 的 `.catch("uncertain")`，经 `gemini-jobs.ts:2591` 宽松解析，在 `gemini-jobs.ts:1887` 记为 uncertain、不发信。整条坏了反而走规则放行会发信。目前未见实际发生（见上），属潜在风险。
2. **"0 条"多数来源分不清真假**：只有 AmiAmi、骏河屋会标 `verified_empty`。补救检测 `apps/collector/src/result-health.ts` 跳过精确同款档案，且要求平时 ≥5 条。
3. **"页面结构变了"三处标准不一**：`db/queries/runs.ts:185` 只认 `parser_structure_error`；`analytics.ts:503`、`db/queries/bindings.ts:391` 还认 `*_schema_changed`。煤炉/骏河屋/雅虎商城结构变化在健康表里被记成普通 failed。
4. 读坏即静默退回默认：屏蔽规则 `core/muted-products.ts:65`（屏蔽失效）、档案配置 `collector/index.ts:270/286`、`core/item-schedule.ts:59`、`db/queries/shared.ts:135/143`、`core/digest-extras.ts:65`；冷却 `db/queries/events.ts:531`（读坏当"刚发过"）；日报去重 `db/queries/digests.ts:554`。
6. 只写日志无补救：`query-attempts.ts:52`（每轮搜词表丢行会让统计偏低）、`source-capture.ts:409`、`index.ts:1595`（当天重试排程）、`index.ts:1791`（参考图比对）、`gemini-jobs.ts:681`（AI 缓存失效 → 账单翻倍）等。

## 方案

2026-10-11 已改（本地，待上线）：第 1 条（`packages/core/src/source-failure.ts` 的 `isParserFailureCode`）、
第 4 条（`parseListingEnrichmentBatchPartial` 对 relevance 不再兜底，坏了整条重问），
以及每日体检新增 `source_parse_failed`（最近 2 天 ≥3 轮且 ≥5% 结构报错，进周报底部）。
第 2、3 条（加字段）未做。

1. 统一一个"是不是结构变了"的判断函数，修正健康表 `state`（纯 bug 修复）。
2. `source_health_snapshots` 加 `empty_kind`（verified / unverified）和 `parser_rejected_count`。
3. `watch_run_query_attempts` 加 `error_code`、`failure_kind`（fetch / parse / blocked / timeout）。
4. 关键词 `relevance` 去掉兜底 → 会改变发信结果，需按档案开关，先你档案试。

## 统计用 SQL

```sql
SELECT b.source_id,
  count(*) FILTER (WHERE r.status <> 'skipped') AS runs,
  count(*) FILTER (WHERE r.error_code = 'parser_structure_error' OR r.error_code LIKE '%\_schema\_changed') AS parse_failed,
  count(*) FILTER (WHERE r.status = 'success' AND r.result_count = 0) AS empty_success
FROM radar_core.watch_runs r JOIN radar_core.watch_bindings b ON b.id = r.watch_binding_id
WHERE r.started_at::timestamptz > now() - interval '14 days'
GROUP BY 1 ORDER BY 2 DESC;

SELECT kind, count(*) jobs, sum(total_items) items, sum(failed_items) failed_items
FROM radar_core.gemini_jobs
WHERE created_at::timestamptz > now() - interval '14 days' GROUP BY 1;
```
