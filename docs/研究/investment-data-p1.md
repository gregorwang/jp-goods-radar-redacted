# 倒卖投资数据 P1

P1 的目标不是直接推荐“买什么”，而是先把原价、当前可买价、竞拍价和真实成交价分开保存，建立可以做历史回测的数据底座。应用继续负责自动采集、证据留存和确定性计算；分层回测、生存分析和策略优化仍在 Databricks 中完成。

## 价格事实口径

| `fact_role` | 含义 | 是否可直接当成交价 |
| --- | --- | --- |
| `acquisition_ask` | 煤炉、骏河屋二手等当前可买入报价 | 否 |
| `new_retail_ask` | Amazon、Yahoo! Shopping 等新品当前售价 | 否 |
| `auction_current_bid` | 尚未结束的 Yahoo! 拍卖当前出价 | 否 |
| `unclassified_ask` | 暂时无法可靠划分的新旧品报价 | 否 |
| `source_sold_status_price` | 来源页面显示已售罄时留下的价格 | 否 |
| `official_list` | 骏河屋详情页的“定価”等官方定价依据 | 否 |
| `source_compare_at` | Amazon/Yahoo! Shopping 页面自己的划线价、原价 | 否，不等同于官方定价 |
| `verified_sale` | 满足严格来源证据条件的已结束拍卖记录 | 仅在商品身份也已按时点确认后 |

价格事实保留币种、税费口径、运费口径、来源 URL 和采集时间；采集链路可提供时同时带上内容哈希。整个视图有 `fact_semantics_version`，严格成交证据另有独立的 `evidenceVersion`。这样后续不会把“标价”“划线价”“当前竞价”误当成真实成交价。

## 原价与新品对照

当前不需要为了骏河屋另开一个“原价爬虫”。现有商品详情采集已经能读取“定価”，P1 将其结构化为 `official_list`，同时保留在 `originalPrice` 兼容字段中。

新品市场价格应通过同一商品的精确身份匹配，从 Amazon、Yahoo! Shopping 等来源持续采样，作为 `new_retail_ask`。页面划线价只记录为 `source_compare_at`，不能冒充官方定价。

这里的关键不是只有一个“原价”列，而是同时保留：

- 官方定价；
- 新品当前最低可买价；
- 二手当前最低可买价；
- 真实成交分布；
- 各价格首次被系统知道的时间。

## 严格成交证据

P1 只把 Yahoo! 拍卖已结束结果中同时满足以下条件的记录视为 `verified_sale`：

- 页面明确处于结束状态；
- 出价数至少为 1；
- 有合法的最终价格；
- 有合法的结束时间；
- 有稳定的来源商品 ID，并保留来源 URL 与证据版本。

Yahoo! 官方将“落札相場”定义为已落札商品，并说明未落札商品不包含在内；P1 在此基础上仍额外要求至少一次出价，采用更保守的证据边界。参见 [Yahoo!オークション帮助：過去の落札価格を調べるには](https://support.yahoo-net.jp/PccAuctions/s/article/H000005305)。

普通商品的 `sold_out`、下架或页面消失不能证明成交，也不会生成成交记录。对于 Yahoo! 拍卖精确商品监控，Collector 会额外执行一次有界的已结束结果采样（每轮最多一页、至少一次出价）。这些记录会进入语义清洗和商品身份判定，但不会触发可购买通知；只有确认属于目标同款、且在回测决策时点已经知道该身份的成交，才能进入目标商品的退出价格样本。套装、异色、异尺寸、缺件、低置信或多件包含物会被拒绝或保留为待确认。

`product-listing-membership-v3` 进一步收紧身份边界：确定性结果必须是 `exact`，AI 只能把 `probable_exact` 且高置信、单件、无缺件的候选升级为同款；`related` 和 `uncertain` 不再因为“看起来相关”而成为同款。颜色、尺寸和品类是独立的变体字段，不再误填到角色字段。修正指纹时，系统先按规范化的具体商品名复用已有商品 ID，再以最新投影补充字段，因此不会因为纠正颜色或尺寸而割裂历史。

## Databricks 读取入口

PostgreSQL 视图 `radar_analytics.strategy_price_facts_v1` 是 P2 的主要事实入口。它统一输出不同价格角色，并提供三个防止前视偏差的时间字段：

- `occurred_at`：价格或成交实际发生时间；
- `knowledge_at`：系统最早能够知道该事实的时间；
- `identity_known_at`：系统确认其属于当前商品实体的时间。

Databricks 回测必须按 `knowledge_at <= 决策时点` 和 `identity_known_at <= 决策时点` 截断，不能使用后来补录或后来匹配到的事实。

P1 仪表盘同时保留两层计数：

- `verified_sale_count`：来源层已经证实“拍卖结束且有正出价”的原始成交证据；
- `point_in_time_verified_sale_count`：商品身份也在当时确认、可用于目标同款回测的严格成交证据。

前者不能代替后者。系统采集跨度按 `knowledge_at` 计算；历史成交的 `occurred_at` 即使覆盖更早月份，也不代表系统已经连续观察了同样长的时间。

## 到手成本口径

`landed-cost.ts` 的版本化到手成本估算已经接入商品情报和目标价事件，覆盖：

- 买入价；
- 日本境内运费；
- 代购固定与比例费用；
- 国际运费；
- 税费和成本缓冲；
- 日元成本区间与带汇率缓冲的人民币换算。

未接入业务的 `resale-economics.ts` 三情景转卖利润原型及其测试已于 2026-09-03 删除。它此前只被单元测试调用，应用和 Databricks 均未使用；应用不提供净回款、转卖净利润或 ROI 预测。

Databricks 管道和机会分级在独立仓库 [`gregorwang/jp-market-databricks`](https://github.com/gregorwang/jp-market-databricks) 维护；其中 S / A / B 分级依据挂牌折价比例和价差，不代表转卖净利润。

## 进入 P2 的条件

P2 开始前至少要满足：

- 关键商品能够稳定做精确身份匹配；
- 主要来源连续采样，且采集失败率可解释；
- 每个策略分层有足够的严格成交样本；
- 成本参数按实际渠道校准；
- 回测按“当时已知信息”重建，包含未售出和退货/损耗，而不只分析幸存商品。

达到这些条件后，再在 Databricks 做持有期生存分析、分层回测、阈值选择和资金占用优化；这些逻辑不进入业务应用。
