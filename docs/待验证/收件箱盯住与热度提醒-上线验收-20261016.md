# 收件箱「盯住」+ 热度提醒（有人盯上了）· 上线验收

> 2026-10-16 写。代码已推上线，**还没在线上真跑通**。验完挪进 `归档/`。

## 是什么

- 用户在每小时推送里看中的商品，到主站「收件箱 → 推给我的」点 **「盯住」**，这件就进商品库，建一个单品档案，**固定每小时**打开一次详情页。
- 详情页里的点赞数（煤炉 いいね / PayPayフリマ 收藏 / 雅虎拍卖 ウォッチ）和评论数（只有煤炉有）每次都记下来，**比上次多了就发邮件「有人盯上了」**。降价、卖掉照常提醒。
- 起因：10-16 一件加藤惠公仔上午有人点了一个赞，下午就卖掉了。这两个数只有详情页里有，每小时的关键词搜索拿不到。

| 地方 | 改了什么 |

| `radar_core.listing_interest_observations` | 新表（迁移 `20261016150000`，**已手工上线**）。数字变了才写一行，第一次看到也写一行作基线 |
| `apps/collector/src/index.ts` | 单品巡回时记录热度，比上次多了生成 `interest_rise` 通知（`packages/core/src/events.ts` 的 `interestRiseEvent`） |
| 通知 | 存的是 `event_type='price_drop'` + `semantic_event_type='interest_rise'`（和涨价同一个办法，events 表的 CHECK 只认老几种）。监控规则 V2 不管它，直接走旧通知路径。**只发邮件**，没接飞书卡片 |
| `apps/web` | 收件箱每行加「盯住 / 盯住中」按钮（`/api/inbox/watch`），盯着的那行显示最近一次的点赞、评论数；通知中心认得「有人盯上了」 |

上限和手机 App 的「等降价」共用：同时最多盯 30 件（`ACTIVE_ITEM_WATCH_LIMIT`）。

## 怎么验

1. 收件箱挑一件煤炉商品点「盯住」，按钮变成「盯住中」。
2. 等一轮（一小时以内），这一行出现「盯住中 · 点赞 N · 评论 N」：
   ```sql
   SELECT l.title, o.* FROM radar_core.listing_interest_observations o
   JOIN radar_core.listings l ON l.id=o.listing_id ORDER BY o.observed_at DESC LIMIT 20;
   ```
3. 点赞变多以后收到邮件，标题形如 `[有人盯上了 · いいね +1] 商品名｜¥xxxx`：
   ```sql
   SELECT created_at, status, payload_json FROM radar_core.events
   WHERE semantic_event_type='interest_rise' ORDER BY created_at DESC LIMIT 10;
   ```
   想快点验证，可以用另一个账号给这件点个赞。

**算通过**：①②③都在线上出现过一次。

**10-16 进度**：② 已过。19:42（日本时间）手动提前跑了一次「リゼロ リュック エミリア モデル」，记下点赞 8、评论 2；
商品页存下了卖家评价「好评 554 · 差评 1」、出品 345 件、2018 年注册。① 的按钮用户还没在页面上点过，③ 的邮件要等哪件商品的点赞或评论真的涨了才会发。
另外：以前用「等降价」建的两件还是自适应频率（约三小时一次），只有从收件箱点「盯住」的才固定每小时。
