# 格银西里尔（JP Goods Radar）产品功能与用途说明

## 一、产品概述

格银西里尔是一个面向个人使用者的日本商品搜索与持续监控系统。它服务的并不是“看一眼价格就下单”的短期需求，而是需要跨多个日本平台寻找、比较、等待和复查商品的人，例如寻找动漫周边、收藏品、中古商品、限定版书影音、服饰、预约商品，或希望长期观察某个商品版本的供应和价格变化的用户。

用户可以把它理解成一套私人商品雷达：先用一个关键词或一个确定商品建立搜索范围，再由系统按设定频率去各个来源巡回；当真正出现新增同款、价格变化、库存恢复或满足目标价的报价时，系统记录事实并发送通知。它把“搜索结果”“正在关注的目标”“来源商品的历史记录”和“实际发生的变化”分开管理，因此既适合临时找货，也适合几周甚至更长时间的等待与留档。

产品的核心目标是降低跨站反复检索的时间成本，并让用户知道每个结论来自哪里、在什么时候被看到、是否真的可购买。它不把不完整的网页窗口包装成全网覆盖，也不会把来源标价、划线价或未结束竞拍价误称为真实成交价。

## 二、主要解决的问题

日本商品的供给高度分散：新品店铺、中古店、个人二手平台、拍卖平台和官方通贩各自拥有不同的库存、价格、页面结构和更新节奏。同一件商品可能因为名称写法、角色别名、颜色、尺寸、套装内容或品相不同而难以比较。用户若手工追踪，通常会遇到四类困难：一是要在多个网站重复输入关键词；二是容易漏掉刚上架或刚补货的商品；三是很难回忆某个报价是否真的降过价；四是无法分辨“当前标价”“公开已售状态价格”和“有严格证据的成交记录”。

格银西里尔围绕这些问题建立统一工作流。它先从各来源获取公开可见的商品信息，再保存结构化字段、采集时间和必要的证据元数据；随后以商品指纹、关键词和规则把结果组织成可持续追踪的档案。用户不需要每天逐站刷新页面，而是把注意力放在真正值得处理的变化上。

## 三、核心功能

### 1. 跨站商品搜索与比较

系统可在乐天市场、Rakuten Books、Yahoo! Shopping、Yahoo!オークション、Yahoo!フリマ、Mercari、骏河屋、CharaON、COSPA、Animate、Amazon Japan 等日本来源中执行搜索。用户可选择来源、输入日文或常用关键词，并按价格区间、品相、在售状态、时间和来源筛选结果。搜索结果支持按相关度、价格高低、最新程度或来源顺序查看，也能区分“整理后的结果”和保留给人工复核的完整检索池。

对同一目标，系统会尽量将标题、角色、作品、厂商、颜色、尺寸、品类、JAN 等信息整理为稳定商品身份，并标示精确同款、变体、套装、相关商品或待确认候选。这样用户在比较时不会只看到一串混杂的标题，而能优先关注真正可比的报价。来源状态也会单独呈现：可搜索、近期不稳定、暂时冷却、未开放等状态均不会被静默隐藏。

### 2. 关注档案与自动巡回

搜索后，用户可建立三类关注档案。第一类是关键词雷达，用于等待某个关键词范围内的新上架商品；第二类是精确同款雷达，以确认的商品身份为中心，在多个来源继续寻找同款报价；第三类是单品价格与库存监控，盯住某一个仍可购买的来源商品。除此之外，用户也可以建立行情采样档案，持续积累某一关键词范围内可见的数量、价格、品类和进出窗口，而不把它变成逐件商品提醒。

每个档案可设置从半小时到每天的巡回频率、首次运行时间、参与来源、查询范围和筛选条件。来源之间独立运行、独立记录错误，某一来源受限不会拖垮其他来源。用户可以暂停或恢复档案、临时手动运行一次、添加或移除来源，并在详情页查看每次巡回的结果与后续计划。首次运行只建立比较基线，避免把系统刚看到的存量商品误报成“新品”。

### 3. 变化识别、规则与通知

系统会在后续巡回中识别新上架、确认降价、价格上涨、可购状态变化、补货和同款报价低于目标价等事件。价格下降会经过二次确认，重复抓取不会反复制造同一条提醒；库存、价格和来源错误也各有独立状态。用户可为每份关注档案设置版本化事件规则，例如哪些来源可以触发、是否启用目标标价或到手成本阈值、同类变化的去重窗口、静默时间和通知方式。规则更新不会改写历史事件，因此之后仍能复查当时为何产生提醒。

符合条件的事件可以通过邮件和已配置的微信 Hermes 通道送达。通知送达状态与商品事实分开保存：邮件失败可以重试或跳过本次发送，但不会删除已经发现的价格、库存或上新记录。系统也支持汇总式通知，减少同一轮多个新增商品造成的打扰；对于一次性挂牌长期保持下架或售罄的情形，会按来源特征结束不再有意义的单品监控，而不会误停商家目录型商品。

### 4. 商品库、价格快照与证据链

每一件被系统见过的来源商品都会进入商品库。详情页保存来源名称、商品链接、图片、标题、卖家或店铺、价格、品相、库存状态，以及历次价格或状态快照；当累积到足够真实观察点后，用户可以查看价格变化曲线和时间线。商品记录回答“这件具体商品发生过什么”，关注档案回答“系统接下来如何继续检查”，全局事件台则用于跨商品筛选和处理提醒。

为了保持可追溯性，采集过程会保存来源 URL、响应状态、字节数、内容哈希和抽取出的结构化字段。完整网页 HTML 只在采集过程中解析，不作为长期网页副本写入数据库。这样既能为价格、库存和解析结果提供证据边界，也避免把不必要的原始页面内容长期存储。来源出现异常空结果、验证页、限流或解析失败时，系统会保守失败并保留旧事实，而不是把它们误判成全站商品下架。

### 5. 商品价格与库存情报

对已建立稳定身份的同款，产品提供基于证据的商品级价格与库存情报页：它会汇集跨来源的当前在售报价、库存状态、公开已售状态标价、样本可比性和参考中位值，并明确展示每一条样本被纳入、排除或仅作为当前报价的原因。品相、完整度、价格口径混合，或样本过少时，页面会保留单一“建议买入线”，而不是给出貌似精确的结论。

系统还支持版本化到手成本配置，可把买入价、日本境内运费、代购或平台费用、国际运费、税费、包材、卖出平台费、卖出运费及损耗准备放进同一成本口径。它的作用是帮助用户复核实际总成本，而不是只比较页面上的日元标价。

对于 Yahoo! 拍卖等可提供严格条件的来源，系统会把“已结束、至少有一次出价、有合法最终价格和结束时间”的记录单独标注为已验证成交证据。普通售罄、页面消失、当前标价和未结束竞拍都不会被当成成交价。此边界能避免价格参考被错误放大，也为后续外部分析保留更可靠的数据基础。

### 6. 自动语义清洗与来源控制

系统可在新商品入库后执行逐条语义清洗，用于补充和规范商品描述、身份候选、品相或相关字段；这是一项后处理能力，不会替代原始来源证据，也不会因为用户查看商品而临时生成结论。来源控制台则集中显示每个来源的适配状态、搜索与监控能力、健康度、冷却时间、最近测试和通知通道状态。实验性来源的覆盖范围、分页限制和稳定性会被明确标出，方便用户据此调整预期。

## 四、典型使用方式

例如，用户想寻找某个限定手办，可以先在跨站搜索中输入日文名称、角色别名和排除词，查看新品、中古和个人二手平台的结果；确认目标版本后，将一条可靠结果转成精确同款雷达，并设定每三小时巡回一次。第一次巡回建立现有供给基线，之后新出现的确认同款、恢复可购买的商品或低于目标价的报价才会触发通知。若其中某个店铺商品特别值得等候，还可以单独建立库存和降价监控，在商品详情中查看真实价格快照。

如果用户是在研究某类收藏品的供给变化，则可以建立“行情采样”而非逐件提醒：系统持续保存可见样本和价格事实，用户再到商品情报页或外部分析环境中复核价格口径、严格成交样本和时间范围。两种用法可以并存：前者帮助买到想要的商品，后者帮助形成长期、可检查的市场观察记录。

## 五、产品边界与适用建议

格银西里尔是单人自用的搜索、监控和证据留存工具，不是电商平台、代购服务、自动下单机器人，也不是保证收益的投资顾问。公开网页和实验性来源只能提供有限的可见窗口，不能代表全站库存；来源临时限制、页面改版或网络问题也可能造成延迟。用户在下单前仍应亲自核对商品的实际页面、运费、品相、缺件、卖家信誉、预约规则和跨境费用。

产品本身不生成市场分析报告，也不把自动清洗结果包装成买卖建议。需要做回测、图表、深度行情研究或策略优化时，应使用外部 Databricks 工作区读取已留存的确定性证据。换句话说，格银西里尔负责“持续、诚实地看见并保存事实”，用户和外部分析工具再负责“基于事实作出判断”。

## 六、总结

这套产品的主要用途，是让日本商品的跨站寻找和长期等待从零散、重复、难以复核的浏览行为，变成有目标、有节奏、有证据的个人工作流。它通过统一搜索、同款识别、关注档案、自动巡回、价格库存快照、变化通知和来源健康管理，帮助用户更快发现合适商品，也更清楚地知道自己为什么收到提醒、价格参考是否可信，以及还应继续等待还是自行核对后行动。
