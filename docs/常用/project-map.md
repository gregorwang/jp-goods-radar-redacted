## 一、一句话说清楚这个系统

你告诉它想找什么（一个关键词，或一件确定的商品），它按设定的频率去 11 个日本购物网站巡逻。看到新上架、降价、补货，或者低于目标价的同款，就发邮件给你。所有看到的商品和价格都会存档，之后可以回查。

整个系统由四块程序组成：

| 程序 | 放在哪 | 干什么 |
|---|---|---|
| 管理网站 `apps/web` | Cloudflare（网址 `eru.example.com`） | 你登录后搜索、建档案、看商品和事件的地方 |
| 采集器 `apps/collector` | Cloudflare | 系统的"心脏"：每分钟醒一次，派活、采集、调用 AI、发邮件 |
| 东京中转服务 `apps/mercari-service` | Vercel 东京机房 | 煤炉（Mercari）只能从这里访问；其他几个网站出问题时也走这里兜底 |
| 新加坡采集服务 `apps/source-runner` | 你的 VPS | 专门处理 AmiAmi 和雅虎拍卖这类需要特殊访问方式的网站 |

### 2. 机场节点池（代理出口）

**你手上有：** 一个机场订阅（"在人间"），每月 30 元，共 19 条线路，覆盖 7 个地区：香港、台湾、日本、新加坡、美国、英国、德国。日本有 3 条线路，它们的入口不同（CN2、9929 等），**出口很可能是同一个日本 IP**，不能当成 3 个独立出口算。现在只给你电脑上网用（Clash Verge）。

**本项目目前一条都没用。**

- 采集代码里只有一处可选的代理开关（AmiAmi 的 `AMIAMI_PROXY_URL`），生产环境没开。README 里写着"生产 VPS 不用代理也能工作"。
- VPS 上的 `sing-box` 是**代理服务端**（对外提供 443 端口入口，出口只有直连），用途应该是你个人翻墙，不是采集的出口池。
- VPS 上有一个 `kindle-egress`（mihomo），属于 Kindle 网关项目，本项目不经过它。
- 2026-09-07 和 09-09 的两份评估文档设计过"节点池"方案，结论是**等数据显示出口不够了才做**。目前它在任务清单里状态是"未开始"。

> 以后如果要给本项目用，要先在 VPS 上装一个客户端，接入同一份订阅。注意：订阅一般有设备数或流量限制，电脑和 VPS 会共用这份额度。
