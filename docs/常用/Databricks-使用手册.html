Databricks 使用手册

JPGR 的数据每晚同步到 Databricks。这份手册讲清楚上面有什么、怎么进去、哪些数字容易看错，并附上能直接复制去跑的常用 SQL。2026-10-11 写，示例结果都是当天实际跑出来的。

怎么进去三层结构口径坑 每天体检判定质量行情价格历史档案表速查让 Claude 分析

怎么进去

① 生产库VPS 上的 PostgreSQL，系统每天在用
② 每晚同步日本时间 05:30 整库复制过去，约 20 分钟
③ Databricks镜像 + 只增不删的历史 + 整理好的表
④ 你来用Genie 用中文问，或 SQL 编辑器直接查

写 SQL：打开 https://dbc-your-workspace.cloud.databricks.com/sql/editor，右上角计算选 Serverless Starter Warehouse，把下面的 SQL 粘进去，按 Ctrl+Enter。机器闲置 10 分钟会自动关机，第一次跑要等十几秒开机。

Genie 问行情：JPGR 市场情报 Agent：价格、在售、平台健康、亚马逊、雅虎拍卖。

Genie 问判定：JPGR 判定体检：判得准不准、日报发了什么、哪里断了。

Genie 每次回答都会给出它跑的 SQL。数字要紧的时候，把它的 SQL 复制出来自己看一眼。

三层结构

层位置是什么什么时候用
整理层workspace.jpgr_ai整理好的表，每个字段都有中文说明先用这层，90% 的问题够用
历史档案workspace.jpgr_history生产库会定期删的 10 张表，这里只增不删要看 90 天 / 180 天以前的判定、日报
原始镜像workspace.radar_core 等和生产库一模一样的副本，每晚覆盖整理层没有的字段

在 SQL 编辑器左栏的目录里点开任意一张表，就能看到每个字段的中文说明。完整的字段说明在仓库 docs/常用/数据字典-Databricks.md。

最容易看错的几个数

  • 时间都是 UTC，比日本时间晚 9 小时。列名带 _jst 的已经转好了；其他的用 from_utc_timestamp(列, 'Asia/Tokyo') 转。
  • 拍卖当前出价不是价格：price_basis = 'auction_current_bid' 的价格还会涨，不能当成交价，也不能当可买价。
  • 已售出不等于成交：sold_out 只是平台显示的状态。最接近成交价的是雅虎拍卖的公开落札，但也不证明买家付了款。
  • 亚马逊没有成交数据：成交列是 NULL 表示看不到，不是 0。
  • 观察次数不是件数：同一件商品每被搜到一次就算一行。要数件数，用按件的表（judgment_listings_v1、current_listings），或者 count(DISTINCT source_id, source_item_id)。
  • 误报只认你的标注：label_verdict = 'hide' 才算误报证据。没标过的不算对也不算错，算比例时分母只用标过的件数。
  • “AI 没表态”和“AI 说无关”是两回事：ai_relevance 为空表示没送 AI。

各平台最近 7 天搜索成功率

看哪个平台最近老失败。cooldown 是平台在冷却期没去搜，不算失败。

SELECT source_id,
       count(*) AS searches,
       count_if(source_status = 'success') AS ok,
       count_if(source_status = 'empty') AS empty,
       count_if(source_status = 'failed') AS failed,
       count_if(source_status = 'cooldown') AS cooldown,
       round(count_if(source_status = 'failed') / count(*), 3) AS fail_rate
FROM workspace.jpgr_ai.search_performance
WHERE searched_at >= current_timestamp() - INTERVAL 7 DAYS
GROUP BY source_id
ORDER BY fail_rate DESC

常用 SQL · 判定质量

判得准不准、日报发了什么、哪些候选值得复查、AI 用了多少。数据都来自只增不删的历史档案。

误报率：发出去的日报里有多少被我标了不想看

分母只用标过的件数（labeled_items）。没标过的不能算对也不能算错。

SELECT profile_name,
       count(*) AS digest_items,
       count(label_verdict) AS labeled_items,
       count_if(label_verdict = 'hide') AS hide_items,
       round(count_if(label_verdict = 'hide') / nullif(count(label_verdict), 0), 3) AS hide_rate
FROM workspace.jpgr_ai.digest_items_v1
GROUP BY profile_name
HAVING count(label_verdict) > 0
ORDER BY hide_rate DESC

拍卖出价会涨，这里只看挂牌价的变化。

FROM workspace.jpgr_ai.price_changes AS c
JOIN workspace.jpgr_ai.current_listings AS l ON l.listing_id = c.listing_id
WHERE c.observed_at >= current_timestamp() - INTERVAL 7 DAYS
  AND l.price_basis = 'listing_price'
  AND c.price_change_jpy < 0
ORDER BY c.price_change_percent

历史档案：生产库已经删掉、只在 Databricks 留着的数据量

_archived_last_seen_at 早于最近一次同步 = 生产库已删。

SELECT 'watch_runs' AS table_name,
       count(*) AS total_rows,
       count_if(_archived_last_seen_at < (SELECT max(_archived_last_seen_at) FROM workspace.jpgr_history.watch_runs)) AS gone_from_production,
       min(try_cast(started_at AS TIMESTAMP)) AS earliest
FROM workspace.jpgr_history.watch_runs

判定体检（Genie「JPGR 判定体检」用的 4 张）

表一行是什么用来回答
judgment_listings_v1一个档案 × 一件商品，结论取最近一次数件数、误报率、哪些值得复查
judgment_observations_v1一次搜索里看到的一件商品某件商品的判定怎么随时间变
digest_items_v1已发出日报里的一件商品日报发了什么、被标了多少不想看
profile_daily_pipeline_v1一个档案一天抓取 → 判定 → 日报 哪段断了

行情与运行（Genie「JPGR 市场情报 Agent」用的 22 张）

表说明
alert_exact_product_reappearances_v1商品提醒候选①：单品档案盯的那件、或精确同款雷达的严格同款，重新变得能买。已排除关键词相关和进行中的拍卖。
alert_public_awarded_sales_v1商品提醒候选②：被盯的同款在雅虎拍卖出现公开落札（拍卖结束且有出价）。不证明已付款或最终成交。
alert_target_purchase_opportunities_v1商品提醒候选③：现在能买的固定价商品达到你设的目标挂牌价或目标到手成本。已排除进行中的拍卖。
amazon_market_signal_facts_v1亚马逊每个商品（ASIN）一行。亚马逊不公开成交，成交列恒为 NULL；只能用报价、库存和“过去一个月购买”标记间接看需求。
amazon_market_signal_summary_v1亚马逊汇总一行。成交相关列为 NULL 表示看不到，绝不是 0。
current_listings所有平台的商品，每件一行，带当前价格和状态。问“现在能买的有多少”用 is_currently_buyable。
daily_market_prices每个平台每天一行的价格分布（日本时间分日）。按观察次数算，不是按商品件数。
data_freshness几个主要数据集的行数和最新时间，用来看数据新不新。
executive_summary一行总览：商品数、能买的件数、平台健康、最近一次同步。
latest_source_health每个平台最近一次健康检查的结果，每平台一行。问“现在哪个平台坏了”用这张，别用历史记录。
market_source_transaction_semantics_v1各平台能不能看到成交：防止把需求代理说成销量。
p1_price_fact_readiness_by_role价格研究用：价格事实按价格角色分组的数量、身份覆盖和偷看未来的风险。
p1_price_fact_readiness_summary价格研究用：价格事实是否够用的一行体检。平台显示已售不算确认成交。
price_changes商品价格变化记录：每次看到价格和上次不同就一行。
product_market_overview每个被确认的同款商品一行：有多少件、现在能买的价格区间、在哪些平台。
search_performance每次搜索 × 每个平台一行：结果数、新增、耗时、走的线路。
strategy_price_facts价格研究用的价格事实，每条价格一行。不同 price_role 不能混算；回测只能用 knowledge_at 之前的数据。
sync_runs生产库同步到 Databricks 的每次运行记录。成功的筛 status='SUCCEEDED'。
yahoo_auction_analysis_facts_v1雅虎拍卖每场拍卖一行：疑似重挂、确认同款、公开落札分别打标，互不替代。
yahoo_auction_batch_dedup_v1雅虎拍卖每次搜索一行的入库核对：同批重复应为 0。
yahoo_auction_event_facts_v1雅虎拍卖每次搜索看到的每场拍卖一行（同一场会在多次搜索中重复出现）。
yahoo_auction_market_layers_v1雅虎拍卖五种口径的数量，供仪表盘用。五层口径不同，不能相加，也不是漏斗。

让 Claude 帮你做更深的分析

Genie 适合问一句、看一个数。要多步分析的时候，比如“为什么这个月误报变多了”“哪些搜索词在白花钱”，直接在 Claude Code 里说“用 Databricks 查……”就行。

Claude 会先读 docs/常用/数据字典-Databricks.md 弄清字段含义，再用你本机已经登录的命令行（databricks --profile jpgr-local）跑 SQL。查到的结论会附上它用的 SQL，方便核对。

本机登录过期时，在 Claude Code 里输入 ! databricks auth login --profile jpgr-local 重新登录。
