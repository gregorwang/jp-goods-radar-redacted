## 1. 一张图看懂

```
collector 巡回 → 通知（关键词日报 / 精确同款上新 / 降价等商品变化）
  └→ 看这个档案的两个开关（watch_profiles.notify_email / notify_feishu，档案页「通知发到哪」）
        ├→ 邮件开：邮件（Resend）
        ├→ 飞书开：push-relay（Cloudflare Worker + Durable Object，手动发布）
        │     ├→ 安卓 App（WebSocket）………………… 10-13 起你在手机上停用，服务器照推
        │     └→ 飞书：每小时日报攒 90 秒合成一张卡；精确同款、商品变化一条一张卡
        │           ├→ 每个群：群自定义机器人（webhook）发，只发这个群勾的档案、没按钮、不花额度（主力）
        │           └→ 你的私聊：应用机器人发，带「不想看」「等降价」按钮（备用；10-14 应用被封中）
        │     发完回报 collector：至少一处收到 = 送到；一处都没收到 = 没送到
        ├→ 只开飞书、飞书没送到（或 20 分钟没回报）：改发邮件，邮件开头写原因
        └→ 两个都关：只巡回，不通知
来源故障提醒、精确同款周报不归档案开关管，照发邮件。

每条通知在每个渠道的发送记录：radar_core.notice_deliveries（status 发送进度，outcome 到没到，fallback_reason 补邮件的原因）
三个渠道共用一个发送循环：apps/collector/src/notice-channel.ts（取件 → 认领 → 发 → 记结果 / 退避重试 / 放弃）
```

**判商品和发消息是分开的**：采集、AI 判定、排除词都在 collector，推送服务只管「发到哪」。
飞书里加群、改卡片只动 push-relay；加一个全新的渠道（Telegram、企业微信……）照 `apps/collector/src/notice-channel.ts` 顶部写的三步来，取件、认领、重试、放弃都不用再写。改判定所有渠道一起变。

## 2. 什么内容走哪

**10-14 起全由档案自己的开关决定**，不再有全局名单。两个开关管这个档案的全部通知：

| 档案设置 | 飞书正常 | 飞书没送到 |
|---|---|---|
| 邮件 + 飞书 | 两边都发 | 邮件照发 |
| 只发邮件 | 发邮件 | — |
| 只发飞书 | 发飞书 | **改发邮件**，开头写「飞书没送到（原因）」 |
| 两个都关 | 只巡回、不通知 | — |

能发飞书的：关键词日报（每小时 / 每天一轮都算）、精确同款上新（确认同款 + 放宽门槛后的疑似同款）、降价 / 涨价 / 到目标价 / 补货 / 卖掉了。
建档回执、单品盯完了这种飞书没有卡片的，只开飞书也照发邮件。

上线时的设置：爱蜜莉雅、鸣濑白羽上新、赛车初音上新、路人女主｜加藤惠 **邮件 + 飞书**；其余档案、以后新建的 **只发邮件**。
⚠️ 这 4 个关键词档案一天约 70～80 份日报，邮件全开会贴着每天 80 封的上限（`MAX_EMAILS_PER_DAY`），
到线以后当天的降价、精确同款会被折进汇总、第二天才发。想少收邮件就在档案页把邮件关掉（只发飞书，没送到会自动补邮件）。

## 3. 开关在哪（先看这里再动手）

| 想做的事 | 怎么做 | 注意 |
|---|---|---|
| **暂停 / 恢复私聊** | 主站「推送」页，或飞书状态卡按钮、菜单「暂停推送」、私聊发「暂停」「恢复」（同一个开关） | **只停私聊，群照发**（10-13 下午改；之前是私聊群一起停）；暂停期间的新货不补发 |
| **某个档案发不发邮件 / 飞书** | 档案页「通知发到哪」，邮件、飞书两个按钮 | 写 `watch_profiles.notify_email / notify_feishu`，下一条通知起生效。飞书开着却没有群收、私聊也没开时，那里会标红提示 |
| **加群 / 删群 / 暂停某个群 / 改某个群收哪些档案** | 主站侧栏「推送」页，每个群一行 | 群名单存在 push-relay 的 DO 里（`feishu_groups` 表），不在 PostgreSQL；加群时自动试发一张。档案按关键词 / 精确同款 / 降价分组，没开飞书的是灰的、点不了（勾选保留，档案开飞书后接着发） |
| 停 App | **手机上**强制停止 + 关通知（或卸载） | 服务器照推，零成本；重新打开 App 就恢复，7 天内的能补 |
| 群改纯标题版（不带图） | `apps/push-relay/wrangler.jsonc` 的 `FEISHU_WEBHOOK_IMAGES` 改 `"0"` 再部署 | 纯标题版一次额度都不花 |
| 停群、只留私聊 | 主站「推送」页把群逐个暂停 | secret `FEISHU_WEBHOOK_URL` 只在第一次启动时搬进群名单，之后改它没用 |
| ⚠️ **别碰** `owner_push_v1.enabled` | — | 推送这一路的总闸：关了**飞书和 App 一起停**，只开飞书的档案全部改发邮件。它的 `config_json`（以前的 `profileIds` / `emailOff` 名单）10-14 起清空、不再读 |

## 5. 飞书这边的硬约束（改飞书之前必读）

1. **额度：每月 1 万次，整个飞书组织所有自建应用共用**（不是每个机器人各 1 万）。
   - 计数的：应用上传图片、应用发消息、改卡片、加急。
   - 不计数的：换 token、事件推送、**点按钮后卡片原地更新**、**群自定义机器人 webhook 发消息**。
   - 现在的用法：每个 IP 每小时一张拼图，私聊每小时一条，约 2,400 次 / 月。到 8,000 次自动只发文字，到 9,600 次停发。
   - **发群不花额度**：群卡片用的是应用已经传好的那张图（同一租户，10-13 实测能显示），所以额度只随 IP 数涨，不随群数涨。
   - 飞书后台「费用中心 → 权益数据」看的是全组织真实用量；push-relay 的计数器只记这个应用自己用的。
2. **回调地址必须用自己的域名** `https://push.example.com/feishu`（push.example.com）。`workers.dev` 在大陆被墙，飞书服务器连不上。
3. **私聊必须按会话号（chat_id）发**，按用户编号（open_id）发会报 230101。会话号来自你发给机器人的消息，所以换账号 / 重绑时要先私聊机器人一句。
4. **push-relay 不跟着 git push 上线**，改完要手动 `pnpm --filter @jpgr/push-relay run deploy`。
5. 卡片 UI 用户很在意（第一版被嫌「这怎么阅读」）。改完先发样卡给他看。

## 6. 出问题先查什么

```bash
# 口令见第 4 节
curl -H "Authorization: Bearer <token>" https://push.example.com/feishu/status         # 开没开、本月几次、队列、群最后一次成没成
curl -X POST -H "Authorization: Bearer <token>" https://push.example.com/feishu/ping   # 立刻发一张状态卡，失败直接返回飞书报错
curl -X POST -H "Authorization: Bearer <token>" https://push.example.com/feishu/sample # 私聊发一张样卡（群的样卡在主站「推送」页逐个「试发」）
cd apps/push-relay && npx wrangler tail                                                     # 实时日志
```

| 现象 | 先看 |
|---|---|
| 只开飞书的档案来了邮件 | 飞书没送到，**自动补发邮件**（每份最多补一次），邮件开头那句写了原因。几种情况：push-relay 回报一个群、私聊都没收到（飞书那一行 `outcome='failed'`，原因在 `outcome_error`）；push-relay 两次拒收；收下 20 分钟没回报；通知生成半小时还没推出去。collector 日志 `owner_push_returned_to_email`；补的那封在 `notice_deliveries` 里是 `channel='email'` 且 `fallback_reason` 有值，飞书那一行变成 `abandoned` / `returned_to_email` |
| 某条到底发没发到飞书 | `notice_deliveries` 里 `channel='feishu'` 那一行的 `outcome`（delivered / failed）；push-relay 那边是 DO 里的 `feishu_outcomes` 表，collector 每分钟经 `POST /outcomes` 来问。collector 日志 `notice_delivered` / `notice_failed`（带 `channel`） |
| 整点没收到 | status 里 `enabled`；日志 `feishu_card_failed`（带飞书错误码）；collector 那轮有没有新货（没新货不发） |
| 私聊收不到、群里有 | 230101 → 会话号丢了，私聊机器人一句 |
| 某个群收不到 | 主站「推送」页那一行的「最近一次」（红字带飞书报错）；那个群勾没勾这个 IP；日志 `feishu_webhook_failed` |
| 「推送」页打不开 / 报「推送服务还是旧版本」 | push-relay 没手动发布新版 |
| 卡片里有灰格子 | 那张商品图没下载到（来源换了图片地址），看 `grid-image.ts` 的 `jpegVariant` |
| 点「不想看」报错 | 日志 `feishu_web_call_failed`；主站 `/api/device/labels` 是否正常 |
| 额度涨得快 | status 的 `quotaUsed`；正常一天 80 次左右 |

## 9. 换一个飞书应用（旧的被封 / 要重建时）

代码不用改，只换凭证。10-13 晚走过一遍，约 15 分钟。

1. 开发者后台新建企业自建应用，加「机器人」能力。App ID / App Secret 发给 Claude。
2. 权限管理 → 批量导入：
   ```json
   { "scopes": { "tenant": ["im:message:send_as_bot", "im:resource", "im:message.p2p_msg:readonly"], "user": [] } }
   ```
3. 事件与回调 → 加密策略：把 Encrypt Key、Verification Token 发给 Claude，**等换上了再去填地址**（不然飞书校验地址时 challenge 回不去）。
4. 事件配置、回调配置都填 `https://push.example.com/feishu`；事件加「接收消息」「机器人自定义菜单事件」，回调加「卡片回传交互」。
5. （可选）机器人自定义菜单：状态 `status`、样卡 `sample`、暂停推送 `pause`。
6. 版本管理与发布 → 创建版本并发布。**不发布，传图会报 234007「没开机器人能力」**。
7. 你的私聊新机器人一句，自动绑定。

Claude 那边：`wrangler.jsonc` 改 `FEISHU_APP_ID`；`wrangler secret put` 换 `FEISHU_APP_SECRET`、`FEISHU_ENCRYPT_KEY`、`FEISHU_VERIFICATION_TOKEN`；
本机 `~/.jpgr/feishu-app.env` 同步；部署 push-relay。DO 发现 App ID 变了会自动清掉旧应用的接收人绑定、token、图片缓存（`desk.ts` 构造函数里），群名单不动。
`lark-cli` 只能调业务接口，改不了应用的权限、事件地址、菜单，这些只能在网页后台点。
