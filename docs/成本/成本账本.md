# 成本账本

> 新建于 2026-10-09。**新功能动手前先在这里算账**（用户原话："算账意识必须有"）。
> 每次实测出新数字就往这里补，写清日期和出处。数字分两种：**实测**（账单 / 计时）和**估算**（单价 × 实测秒数），表里标明。

## 2. Modal 单价（2026-10 官网价，按开机秒数计费）

| 资源 | 每秒 | 每小时 | 本项目谁在用 |
|---|---|---|---|
| T4 显卡 | ≈ $0.000164 | ≈ $0.59 | 图片指纹、细节比对 |
| A10G 显卡 | ≈ $0.000306 | ≈ $1.10 | 看图判断多件（Qwen2.5-VL-7B） |
| CPU / 内存 | 很少 | | 编排、下图 |

**计费的坑**：
- 开机就计费：启动容器、把模型装进显卡的时间都算钱。十几张图的任务，**真正计算不到 1 秒，钱几乎全花在启动上**。
- 算完不会马上关：默认空转约 1 分钟才关，**空转也计费**。要用 `scaledown_window` 设短。
- 每调用一个函数就可能开一台新机器：两个函数 = 两次冷启动、两次空转。能合进一台机器的就合。
- 函数里每次调用都 `from_pretrained` = 每次都重新装模型，热着也慢（实测 8 秒）。模型要放在 `@modal.enter()` 里只装一次。

**日报估价可以按档案关**（10-11 起）：档案详情页「日报附带信息」把原价选成「只要官方定価」或「不显示原价」，
那个档案发日报时请求带 `estimate: false`，不唤醒 GPU。原价补查那一遍（AI 短查询）一律不估价。赛车初音 10-11 起已关。

**为什么建档回执那么贵**：大头是"看图判断多件"那一步（A10G 跑 7B 模型逐张看 1000 张图），其次是细节比对（初音 3459 对）。下图本身几秒。

**漏斗的意义**：精确同款每天约 200 件新候选，但图片模型只看漏斗筛剩下的（AI 拿不准的、标题 / AI 认为对上的），每次几件到十几件。成本由**启动次数**决定，不由图片张数决定。

## 5. 开关：关着时花多少

两个花钱功能都由数据库里的开关控制（`radar_core.runtime_feature_flags`，2026-10-09 迁移 `20261009190000` 插成**关着**）。
**按一下就生效，不用改代码、不用部署**：collector 每次要调 Modal 前都先查一次开关。

| 功能 | 开关 `flag_key` | 关着时 | 打开后 |
|---|---|---|---|
| 精确同款按参考图打分 | `exact_reference_image_v1` | $0，精确同款照旧只看标题 | 每个**有参考图的**精确同款档案、当轮有没打过分的新候选时调一次，单次 ≈ $0.005～0.01（估算），现状每月 ≈ $0.2～0.6（见 §3） |
| 建档回执图片分组 | `listing_image_grouping_v1` | $0，清单页同名折叠 | 一封千件 $0.3～0.5 |

### 打开 / 关掉

**按参考图打分**（10-12 起）：后台任一精确同款档案详情页「参考图」一栏右上角点「打开看图 / 关闭看图」，全局生效。下面的命令是备用办法；建档回执分组目前只能用命令。

```bash
# 打开（把 exact_reference_image_v1 换成要开的那个）
ssh root@203.0.113.10 "sudo -u postgres psql -X -d jpgr -c \"UPDATE radar_core.runtime_feature_flags SET enabled=1, updated_at=now()::text WHERE flag_key='exact_reference_image_v1'\""
# 关掉：enabled=0
# 看现在的状态
ssh root@203.0.113.10 "sudo -u postgres psql -X -d jpgr -c \"SELECT flag_key, enabled, updated_at FROM radar_core.runtime_feature_flags WHERE flag_key IN ('exact_reference_image_v1','listing_image_grouping_v1')\""
```

**两个功能都还要口令**：collector 的 secret `IMAGE_DEDUP_TOKEN` 要和 Modal Secret `jpgr-image-dedup` 的 `DEDUP_TOKEN` 一致。
10-09 为了省钱把 collector 那边的口令删了，所以**第一次打开前要先把口令配回去**（只做一次，以后开关只动数据库）：

1. 生成一个新口令（旧的没存，Modal 也读不回来，所以换新的）：
   `python -c "import secrets;print(secrets.token_urlsafe(32))"` → 复制输出
2. 写进 Modal（覆盖旧值）：`modal secret create jpgr-image-dedup DEDUP_TOKEN=<口令> --force`
3. 写进 collector：`cd apps/collector` 然后 `npx wrangler secret put IMAGE_DEDUP_TOKEN`，粘贴同一个口令
4. Modal 那边要部署过带 `/score` 的版本：`modal deploy apps/image-dedup/service.py`（部署不花钱）

口令配上、开关关着 = 照样 $0。

### 打开以后会发生什么

- **按参考图打分**：只看漏斗筛剩的候选（文字判为确认同款且这一轮新出现的、文字拿不准的；标题含「〇〇様専用」的直接排除），
  每个档案每轮一次，算完 2 秒就关机。网页档案详情页的「参考图」一栏会从"看图暂未开启"变成"看图已开启"。
  Modal 调不通 / 超时（150 秒）/ 额度用完时，这一轮自动退回只看标题，照常发信。日志事件 `exact_reference_image_applied`、`exact_reference_image_failed`。
- **按参考图打分，打开后第一天要核对的事**（给接手的 AI）：
  1. 开之前先 `modal billing report --for today` 看额度还剩多少；第一次真调要先问用户（单次约 $0.005，没实测过）。
  2. 第二天早上巡回后查 collector 日志 `exact_reference_image_applied`：送了几件、对上几件、攒到晚上几件、有没有 `modalError`。
  3. 查库：`SELECT o.title, o.image_sim, o.image_inliers, o.image_verdict, o.decision_status FROM radar_core.watch_run_listing_observations o WHERE o.image_verdict IS NOT NULL ORDER BY o.updated_at DESC LIMIT 30;`
     分数和 [调研](../研究/精确同款按参考图找货-调研-20261009.md) 里的实测区间对不对得上。
  4. `modal billing report --for today --resolution h` 看 `jpgr-image-dedup` 实际花了多少，把实测单价补进上面 §3 的表。
  5. 规则和已知限制见 [交接 §0](../进行中/精确同款参考图-交接-20261009.md)；门槛在 `apps/collector/src/exact-reference-image.ts` 的 `IMAGE_MATCH_*`。
- **建档回执分组**：两分钟内 collector 会接手**最近 3 天内**发出、存量 ≥30 件的回执。更早的要分组就手工插一行 queued（见 `apps/image-dedup/README.md`"重跑"）。

## 6. 怎么查账

```bash
modal billing report --for today --resolution h          # 今天按小时
modal billing report --start 2026-10-01 --end 2026-11-01 # 某段时间，按应用分
modal billing report --for today --show-resources         # 拆到 GPU / CPU / 内存
modal container list                                       # 现在有哪些机器开着（开着就在计费）
modal container stop -y <id>                               # 关掉一台
```

一个函数调用要取消：`modal.FunctionCall.from_id("fc-…").cancel(terminate_containers=True)`。

- **预估**：每轮每个档案最多开机一次，三天最多 9 次，≈ $0.05～0.1。
- **终点**：用户 2026-10-15 在后台档案详情页「参考图」一栏点「关闭看图」（10-12 加的按钮，全局开关）。验证与结算步骤见 [待验证文档](../待验证/贴纸误判修复与参考图试运行-待验证-20261012.md) §2。关后核对：
